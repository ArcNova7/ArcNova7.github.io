做理解分析

文章介绍了 SSH 端口转发（Port Forwarding）的三种方式：

## 本地代理转发

实验环境拓扑如下：

```
[Win10 攻击者主机]         [Kali 跳板机]          [Linux 目标服务器]
192.168.110.130    ←SSH→  192.168.110.131    ←→   172.16.1.200
     (用户)              (tunnel-host)              (Web应用:80)
       
  ⚠️ Win10 与 Linux目标服务器 处于不同网段，物理隔离(vmnet19)
  ⚠️ Linux目标服务器配置了iptables，拒绝192.168.110.130直接访问
```

本地执行

```
ssh -L 8080:172.16.1.200:80 root@192.168.110.131
#       ↑          ↑         ↑          ↑
#    本地端口 目标主机:目标端口  用户名  跳板机IP
```

```
Win10执行命令后，本地SSH进程会：
  1. 在Win10本地 127.0.0.1:8080 创建一个监听socket
  2. 当有请求发到这个端口时，SSH自动打包请求
  3. 通过已建立的SSH加密隧道，发给Kali(192.168.110.131)
  4. Kali的SSH服务收到指令后，以Kali的名义去连接 172.16.1.200:80
  5. Web服务器返回数据，原路退回

所以对目标服务器172.16.1.200来说：
  请求来源是Kali(172.16.1.100)，而不是Win10(192.168.110.130)
  防火墙只拒绝了Win10，Kali可以正常访问
```

## 远程转发

```
ssh -R [远程端口]:[本地IP:本地端口] 用户名@SSH服务器
```

```
# 在 Linux目标服务器(172.16.1.200) 上执行
ssh -R 80:localhost:80 root@172.16.1.100
#      ↑   ↑           ↑     ↑
#   远程端口 本地:本地端口  用户   SSH跳板机(Kali内网IP)
```

## 动态转发（Dynamic Forwarding）

动态转发本质上是通过 SSH 建立一个 SOCKS5 代理服务器，不需要事先指定目标，可以动态代理任意地址和端口的流量。

```
ssh -D [本地端口] 用户名@SSH服务器
```

```
ssh -D 1234 root@192.168.110.131
#      ↑          ↑
#  本地SOCKS5端口   Kali跳板机
```

代理原理解析

```
┌──────────────────────────────────────────────────────────────────┐
│                                                                  │
│  步骤1: Win10浏览器配置SOCKS5代理 → 127.0.0.1:1234               │
│                                                                  │
│  步骤2: 浏览器要访问 http://172.16.1.200                          │
│         浏览器向127.0.0.1:1234发送SOCKS5请求                      │
│         请求内容包含目标地址: 172.16.1.200:80                     │
│                                                                  │
│  步骤3: Win10的SSH客户端                                          │
│         解析SOCKS5协议，提取目标地址172.16.1.200:80               │
│         通过SSH加密隧道，把请求发给Kali                            │
│                                                                  │
│  步骤4: Kali的SSH服务器                                           │
│         收到请求后，以自身名义连接172.16.1.200:80                  │
│         充当"代理中间人"                                          │
│                                                                  │
│  步骤5: 数据返回                                                  │
│         172.16.1.200:80 → Kali → SSH隧道(加密) → Win10           │
│         Win10浏览器收到页面内容                                    │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

渗透测试

```yaml
场景：已拿到内网一台机器权限，想扫描整个内网

方案一：本地转发（局限性大）
  每个目标都要单独建一条隧道：
  ssh -L 8080:10.0.0.1:80 root@跳板
  ssh -L 8081:10.0.0.2:80 root@跳板
  ssh -L 3306:10.0.0.1:3306 root@跳板
  ... 太繁琐了

方案二：动态转发（推荐）
  ssh -D 1080 root@跳板
  
  配合 proxychains 工具，任何命令都能走代理：
  proxychains nmap -sT 10.0.0.0/24      # 扫描整个内网段
  proxychains sqlmap -u http://10.0.0.1  # 通过代理跑sqlmap
  proxychains ssh root@10.0.0.5          # 继续跳到下一台机器
```

- `ssh -D 1080 root@跳板`
  建立 SSH 连接并在本地开启 SOCKS 代理（端口 `1080`），同时会登录到跳板机，给你一个远程 shell（通常是交互式的命令行提示符）。你可以在跳板机上执行命令，同时 SOCKS 代理保持有效。
- `ssh -D 1080 -N root@跳板`
  建立 SSH 连接并开启 SOCKS 代理，但不执行远程命令（`-N` 选项表示 “no command”），因此不会分配 shell，也不会让你登录到跳板机。连接建立后，SSH 仅用于端口转发，不提供交互式会话，通常配合 `-f`（后台运行）一起使用，例如 `ssh -f -N -D 1080 root@跳板` 让隧道在后台静默运行。
